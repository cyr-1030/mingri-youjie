# 明日有解｜完整体验版

这是「明日有解」保留传统文化体验的完整版本，同时提供可直接访问的网页版与原生微信小程序源码。首页从「今天 / 明天」和九个主题进入，完成三幕意象题、图像选物、卦意与传统黄历参考，然后根据个人条件生成穿搭、妆容、配饰和准备清单。另有「答案之书」、八字五行档案和文字衣橱。

## 在线体验

- GitHub Pages：<https://cyr-1030.github.io/mingri-youjie/>
- 网页版使用 Open-Meteo 获取所选城市的天气；微信小程序版通过云函数连接彩云天气。
- 数据默认保存在当前浏览器或小程序本机缓存中，详见在线隐私说明。

## 直接运行

1. 在微信开发者工具中导入本目录 `miniapp/`；`project.config.json` 已配置用户注册的小程序 AppID。
2. 点击「编译」。题目、选物、答案书、八字换肤、黄历、条件确认和文字方案无需后端即可使用。
3. 运行规则测试：`npm test`。运行时代码已打包 `lib/lunar.js`，打开小程序无需先构建 npm。

## 自动五行色调

进入「命盘」，用两列地区选择器选内地省市、港澳台或「海外」，不需要输入地名；时辰可跳过。保存后，资料表单自动收起，只显示命盘结果。系统用 `lunar-javascript 1.7.7` 计算日柱天干（日主）及五行，并自动切换木、火、土、金、水对应的界面色调。未填时辰只显示年、月、日三柱；未填出生资料使用中性色调。结果页不展示原始生日、时刻和城市；点「更换用户 / 重填资料」才打开空白表单，原资料在新资料保存前仍保留。出生资料存在本机小程序缓存，可手动删除。

界面使用便于辨认的现代视觉色：木青绿、火朱赤、土赭褐、金香槟金、水黛蓝；传统五行正色依次为青、赤、黄、白、黑，两者在命盘说明中区分。`lib/elements.js` 的配色仅用于界面主题和五行条，**不直接决定穿搭或配饰颜色**。表层五行计数只展示分布，**不据此判断喜用神**、吉凶或购买依据。四柱使用北京时间与历法库节气规则；「海外」缺具体时区，暂不生成四柱。内地历史民用时间、真太阳时等边界尚未单独处理。

## 个人每日主题

`lib/daily.js` 把出生资料中的日柱与所选日期的日干支对照，按五行生克与天干阴阳映射到传统「十神」的十种关系，再为每种关系写一条具体的行动和搭配提示；出生的日支与目标日相冲时，附加「预留时间余量」的提醒。解读页展示采用了哪一项传统符号关系，方案页把主题落实为准备动作、搭配细节和可选的配饰类别。同一人换日期、同一天换用户可得到不同主题。缺出生资料、海外缺具体时区或无法可靠排盘时显示简版互动建议；缺出生时刻时只用前三柱并明确标注。此模块是**可解释的传统文化灵感**，不是测测 App 的内部算法，也不预测事件、计算喜用神或给出吉凶分数。

## 简版西方星盘

中国内地及港澳台、1992 年以后且提供出生时刻时，`Astronomy Engine 2.1.19` 计算太阳、月亮、水星、金星、火星的真实黄经及回归黄道星座，并绘制十二星座轮。缺时刻、海外缺时区或 1992 年前有历史时差歧义时不生成星体位置；没有精确出生地经纬度时不计算上升点和十二宫位。随包附 `lib/astronomy.js`，其文件头包含 MIT 许可证。

## 具体推荐

条件页提供 15 种风格（选 1–3 种），以及年龄段、城市、室内外和场合；新用户初始为温柔轻熟与法式松弛。选定城市后，气温、降雨和气候因素由彩云天气自动获取；进入条件页或方案页时，超过 30 分钟的预报会自动更新，不要求用户手填天气。天气安全先约束可用单品，再按用户选的首要风格、版型和颜色选择衣橱里的物品；七种场合进一步改变服装、鞋包、妆容与搭配重点，已录入且适用的衣物优先。抽中的物件对应具体搭配细节和行动提醒，每日个人主题提供另一层节奏建议。明日方案不提供临时购买建议；未录入的品类会给出从家中寻找同类替代的办法。搭配单品标注“已有”或“参考”，待核对的衣橱物品不会被说成已经拥有；方案还展示天气、场合、衣橱、风格和个人日期关系各自的建议依据。

「我的衣橱」按大类和具体单品选择，包含上装、裤装、裙装（含半裙和连衣裙）、外套、套装、鞋履、包袋、首饰、穿戴配件、美妆香氛、居家与特殊、随身小物；用户只需录入自己拥有的类别。衣物、鞋包和穿戴配件会参与日常搭配，美妆及其他小物目前只保存，不会混入穿搭清单。单品照片由用户自行添加，也可以不加。方案会把当前条件下实际选中的五或六件单品排成照片搭配板；连衣裙等连身款不会再硬凑一件下装。未录入照片或因天气不合适而被排除的单品不会借用别的图片。用户照片经 `wx.saveFile` 保存在本机小程序文件中，名称与路径存在本机缓存；删除单品时同时移除其本机照片。衣橱页另有独立的「未来补充清单」，按首选风格、尚未录入的基础品类和单件预算给出最多三项长期建议及可复制搜索词；它不参与今日或明日方案。

方案页直接展示文字清单、妆容、发型、准备事项和用户已录入的衣橱照片搭配板。AI 生图入口、提示词生成与调用逻辑已经移除；视觉参考来自用户自己的单品照片和经人工核对的博主匹配。

方案页还提供「延伸灵感」卡：15 种风格各有原创穿搭和妆容规则，卡片会引用本次实际清单、天气及场合。当前没有已核实、可直接匹配的具体穿搭笔记，卡片只提供可复制的搜索词，需用户在小红书中自行搜索；不会伪装成实时博主推荐，也不转载笔记正文或图片。`data/curated-creator-sources.json` 已收录第一篇人工核对的博主导航及其中 10 个正确账号，它只用于后续选择代表笔记，尚不作为穿搭案例。未来可把人工核实的具体笔记元数据（`id`、`styleId`、`kind`、`title`、`author`、`url`）写成 JSON 数组，并运行 `node scripts/import-inspiration-notes.js /绝对路径/notes.json` 导入。导入只接受小红书原文链接，页面会显示原文标题与作者并提供复制链接；导入后仍需人工核对内容与风格是否相符。小红书[开放平台权限说明](https://openaccount.xiaohongshu.com/docs/scope)尚未提供可用的公开笔记读取权限，因此本版不做笔记实时抓取。

`data/creator-candidates.json` 现记录用户提供的 10 个风格分组、38 个博主或品牌账号候选。原清单里的小红书主页 URL 经抽查存在大量错配，已全部停止沿用；2026-09-21 通过站内名称搜索重新找到 28 个账号，其中 6 个已进入主页并确认内容方向，1 个确认身份但仍需复核风格，21 个仍需进入主页复核，其余账号保持未确认。核对细节见 `data/source-verification.md`。主页不能代替具体笔记；后续应先核对场合、天气、单品和妆容标签，再把有明确来源的笔记作为检索候选。小程序若要展示封面、正文或图像，还需单独确认使用许可。现有名单尚未覆盖「城市户外」「运动休闲」两种风格。

方案页已接入第一版博主级检索：`scripts/build-verified-creators.js` 从两份人工核对数据生成 16 个运行时账号，`lib/creator-match.js` 按用户首选风格、次选风格、场景和室内外条件计分，并展示最多 3 个匹配主页。它只用于验证检索和交互链路，不读取博主全部笔记，也不等同于具体穿搭案例 RAG；下一阶段需为每位博主筛选经过核对的代表笔记。

AI 生图功能已从前端、配置、提示词模块和本地云函数目录移除。云环境里历史部署的函数不再被小程序调用，可在云开发控制台单独删除。

## 真实天气接口

`cloudfunctions/getForecast` 对接彩云天气逐日预报，凭据只在云函数环境变量中；成功时自动更新条件页并显示「数据来自彩云天气」。未选择城市或预报失败时，方案标明暂无天气数据，不沿用旧预报或猜测气温。具体配置见 [getForecast/SETUP.md](cloudfunctions/getForecast/SETUP.md)。

`weatherEnabled` 已打开。云函数环境 ID 配置在 `config.js`，令牌仅保存在云函数环境变量中。开发者工具模拟器中已验证城市预报会进入穿搭方案并显示天气来源。彩云天气[用户协议](https://platform.caiyunapp.com/user/user_agreement/)要求显著标注来源，并规定取得令牌后三个月内提交应用链接与截图；不要在产品外重新发布其天气数据。

## 当前 MVP 边界

- 天气云函数已部署，前端自动天气已在模拟器验收。未覆盖城市或接口失败时明确提示暂无天气数据，当前城市与出生城市分开保存。
- 西方星盘显示可计算的星体位置，不展示未经计算的上升点、十二宫位或相位。
- 衣橱支持名称、分类与本机照片，尚无照片自动识别和跨设备同步；照片搭配板是单品拼排，不模拟上身效果。
- 商品仅给可搜索的单品描述，不展示未核验的淘宝或店铺链接。
- 传统黄历依据所选日期由历法库计算，独立标注来源；原创卦意属于自我观察与生活灵感。
- 正式公开前还需完成账号主体/类目审核、隐私告知和真机验收。
